# 小規模の試行の案

ここにある期間・人数・頻度・条件は、**仮の案**。根拠のある最適値ではない。利用者が決め、試行の結果で直す。
まだ何も実施していない（2026-11-25）。

## 1. 進め方

| 段階 | すること | 送信 |
|---|---|---|
| 0. 読者を選ぶ | 試行の対象にする読者を 1 つ選ぶ（[reader-needs.md](reader-needs.md)） | なし |
| 1. 聞く | その読者の 3〜5 人に、質問の案で話を聞く。答えを `audience.need` に反映する。題材を選び直す | なし |
| 2. 見せる | サンプル 1〜3 件のプレビューを、同じ人たちに見せて、下の確認項目を聞く（画面の共有か、プレビューのファイルを渡す） | なし |
| 3. 直す | 分かりにくかった所、要らなかった情報を直す。カードの文字の大きさは、Teams の実機（デスクトップとモバイル）で確かめる | なし |
| 4. 投稿する | 利用者が、投稿先と内容を承認したものを、**人が**投稿する。試行の読者だけのチャネルで、2〜4 週間、週に 1 件まで | 人が行う |
| 5. 振り返る | 感想と、使われた例を読み、続けるか、形を変えるか、やめるかを決める | — |

段階 4 の「2〜4 週間、週に 1 件まで」は、通知を増やしすぎないための、控えめな仮の値。読者が許容すると答えた頻度（質問 6）があれば、それに合わせる。
出す題材がない週は、出さない（量の目標は置かない）。

## 2. サンプルを見せたときの確認項目

見せる前に、説明をしない（投稿だけで伝わるかを見るため）。答えは、読者の区分と一緒に `aar brief feedback` で記録する。

| 聞くこと | 記録の項目 |
|---|---|
| 何を伝える投稿だと受け取りましたか（自分の言葉で） | `understood` と、感想の欄 |
| 自分の仕事との関係が分かりましたか | `relevant` |
| 確かめたことと、確かめていないことの区別が分かりましたか。どこを見て、そう判断しましたか | `status_clear` |
| もっと知りたいときに、どこへ進めばよいか分かりましたか | `reached_detail` |
| 要らない情報や、分かりにくい所はどこでしたか | 感想の欄、`too_much` |
| （判断する）比較や選定に使えそうですか。足りない観点は何ですか | `helped_decision` |
| （試す）試してみましたか。どこで止まりましたか | `tried`、止まった所の欄 |

「確かめていない情報を、確かめたものと受け取った」人が 1 人でもいたら、表示を直すまで投稿しない。

## 3. 続けるかどうかの目安（仮）

数で決めない。次を読んで、利用者が判断する。

- 読者が、投稿の要点と、確かめていない範囲を、自分の言葉で言えたか。
- 「判断する」の投稿が、実際の選定や申請に使われた例が、1 件でもあったか。
- 「試す」の投稿で、手順にたどり着いた人がいたか。止まった所は、投稿の側で直せるものか。
- 関係のない通知が多い、という声がなかったか。

やめる・形を変える目安: 読者が、仕事との関係を見いだせない。確かめていない情報が、確かめたものとして伝わる。通知が邪魔だと言われる。

反応の数や閲覧の数は、参考にとどめる。少数の感想からは、傾向の手がかりしか得られない。

## 4. 自動の配信へ進む前に満たす条件

1 つでも欠けていれば、進まない。満たしたかどうかは、利用者が判断する。

1. 読者のニーズを、読者に確かめてある（`reader_confirmed` の候補があり、誰に・いつ聞いたかの記録がある）。
2. 人が投稿する運用を、試行の期間つづけて、確かめていない情報が確かめたものとして伝わった例がない。
3. 訂正を、実際に 1 回、手順どおりに出せた（訂正版の作成、承認のやり直し、元の投稿との関係の記録）。
4. Teams での表示を、デスクトップとモバイルの実機で確かめた。代替テキストと読み上げも確かめた。
5. 社内の確認が済んでいる: 投稿先、Workflows の利用、詳細ページと画像の置き場所と閲覧の権限、外部のモデルへ送ってよい範囲。
6. 送信の仕組み（重複の防止、再試行、結果の記録、訂正、認証情報の管理）を実装し、検証用の投稿先で確かめた。
7. 「自動」の範囲を決めてある。**承認は、自動にしない。** 自動にしてよいのは、承認済みの候補を、決めた時刻に送ることまで。
8. 止める方法がある（配信の停止、投稿先からの取り下げの手順）。

この条件を満たしても、長期の無人運転（研究のパイプライン）の承認とは別の判断。
