# ADR-0001: 全体構成 — 進行管理と研究の中身を分ける

- 日付: 2026-11-23
- 状態: 採用

## 状況

論文の発見から監査つきの公開候補までを、利用者の操作を「企画の選択」だけにして自動で進めたい。
工程は数時間に及び、PC の再起動や API の利用上限で途中で止まることを前提にする必要がある。

## 決定

3層に分ける。

| 層 | 担当 | 実装 |
|---|---|---|
| 進行管理 | 工程の順序、再試行、保留と再開、定期実行 | Temporal のワークフロー（`aar/temporal/workflows.py`） |
| 副作用 | エージェント呼び出し、実験の実行、DB、Git、GitHub | Temporal のアクティビティ（`aar/temporal/activities.py`） |
| 研究の中身 | 設計の考察、コード作成、批判的検討、監査 | エージェント CLI（Claude Code、Codex）と隔離実行 |

ワークフローは「どの工程を次に実行するか」だけを決め、研究の内容には立ち入らない。
研究1件が1つのワークフローで、Workflow ID は研究 ID と同じにする。

## 理由

- 進行の状態を Temporal の履歴に持たせれば、プロセスが落ちても続きから再開できる。自前の状態機械を書かずに済む。
- 研究の中身をワークフローに入れると、決定性の制約（時刻・乱数・I/O を使えない）と衝突し、履歴も膨らむ。
- LangGraph や n8n は入れない。エージェント内部の制御は CLI が持っており、全体の進行は Temporal で足りるため、役割が重なる。

## 影響

- 工程の粒度はアクティビティ単位。一時停止は「実行中の工程が終わったところ」で効く。中止は実行中の工程も打ち切る。
- 完了した工程の結果は `side_effects` 表に保存し、再実行されても保存済みの結果を返す（ADR-0005）。
