# ADR-0005: 再試行に耐える副作用と、保留の扱い

- 日付: 2026-11-23
- 状態: 採用

## 決定

**冪等性**

| 対象 | 方法 |
|---|---|
| 工程（エージェント呼び出しを含む） | 完了時に結果を `side_effects` に保存。キーは `研究ID:工程:サイクル:回`。再実行されたら保存済みの結果を返す |
| 研究の登録 | `research_projects.proposal_id` の一意制約。同じ企画を何度選んでも研究は1つ |
| ワークフローの起動 | Workflow ID = 研究 ID、重複は拒否、実行中なら既存を使う |
| 事前登録 | ファイルが既にあれば上書きしない |
| 費用・通知・イベント・監査結果 | それぞれ一意キーつきの挿入 |
| 論文の取り込み | DOI・arXiv ID・情報源 ID での upsert |
| PR | 同じブランチの PR が既にあればそれを返す。push は強制しない |

キーに Temporal の Run ID を使わないのは、Continue-As-New やリセットをまたいでも重複させないため。

**途中で落ちた工程** は、作業領域に残ったファイルの上からやり直す。エージェントには既存のファイルを読んでから直すよう指示している。

**保留** — 次の失敗は再試行せず、研究を保留にして通知する。再開は利用者の合図（`aar projects resume`）。

| 種類 | 例 | 再開の前にすること |
|---|---|---|
| auth | エージェント CLI のログイン切れ | ログインし直す |
| budget | 研究の費用上限に到達 | 上限を上げる（`aar projects budget`）か、中止する |
| policy_changed | 方針ファイルが研究の開始後に変わった | 元に戻す |
| setup | 監査 Skill が置かれていない | Skill を展開する |
| resource | ディスクの空きが基準（既定 150MB）を下回った | 空きを作る |
| rate_limit | 利用上限 | 30分ごとに自動で再開を試みる（12回まで） |

## 理由

- エージェント呼び出しは有料で数分かかる。Temporal の再試行でそのまま繰り返すと費用が倍になる。
- 認証切れや費用上限は、再試行しても直らない。自動で先へ進めず、止めて知らせる方が安全。

## 限界

- 工程の途中（エージェントの実行中）で落ちた場合、その工程のエージェント呼び出しはやり直しになる。費用は台帳に両方残る。
- ハートビートは10秒ごと。ワーカーが落ちてから検知まで最大3分かかる。
