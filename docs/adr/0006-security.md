# ADR-0006: 安全の設計 — エージェントにシェルを渡さず、実験は隔離して動かす

- 日付: 2026-11-23
- 状態: 採用

## 脅威

- 論文・README・取得したコードに仕込まれた指示（プロンプトインジェクション）。
- エージェントが書いた実験コードによる、ホストの破壊・秘密情報の読み出し・外部送信。
- 改善担当のエージェントが、品質ゲートを通すために基準や事前登録を書き換えること。
- 秘密情報や作業用パスが公開候補に混ざること。

## 決定

1. **研究側のエージェントに実行の道具を渡さない。** Claude Code は `--tools` で読み書きと検索だけに絞り、
   利用者の設定・フック・MCP を読み込ませない（`--setting-sources ""`、`--strict-mcp-config`）。
   コードの実行はオーケストレーターが隔離環境で行い、ログだけを返す。
2. **外部由来の文章はデータとして渡す。** `<untrusted_data>` で囲み、その中の指示に従わないことをシステムプロンプトで固定する。
   閉じタグの偽装は無害化する。
3. **実験の隔離**（`aar/sandbox.py`、方針の `safety.sandbox`）
   - `docker`: ネットワークなし、ルートは読み取り専用、権限をすべて落とす、メモリ・CPU・プロセス数を制限。最も強い。
   - `seatbelt`: macOS の `sandbox-exec`。ネットワークを禁じ、書き込みを作業領域と専用の一時領域に限り、
     `~/.ssh` などの読み取りを禁じる。**ファイルの読み取りは一般には制限していない**ため、docker より弱い。
   - どちらも API キーなどの環境変数を渡さない。
4. **監査担当は対象の複製だけを読む。** Codex の OS サンドボックスで、書けるのは監査用の作業場所だけ。
5. **品質ゲートの基準は書き換えられない。** 方針ファイルは作業領域の外にあり、研究の開始時にハッシュを固定する。
   判定のたびに照合し、違えば保留。事前登録はハッシュ・コミット・履歴で改変を検出する。
   仮説の判定はエージェントが「支持」へ引き上げられない。
6. **公開の範囲** — main へ push しない。push 先が方針で許した公開範囲（既定は private だけ）にあることを毎回確かめる。
   リポジトリを自動で作らない。公開候補は秘密情報とホームのパスを検査し、見つかれば止める。
   監査記録は毎回原本から写し直す。
7. **費用** — 研究ごとの上限、呼び出しごとの上限（`--max-budget-usd`）、回数・時間の上限。
   実験コードから従量課金の API を呼ぶことは既定で禁止（ネットワークがない）。子プロセスには API キーを渡さない。

## 現在の設定（2026-11-24）

`safety.sandbox` は `docker`。実験ごとに、`requirements.txt` のハッシュで決まるイメージ（`aar-exp:<ハッシュ>`）を作って使う。
依存関係の導入のときだけネットワークを使い、実験の実行時は切る。
確認したこと: コンテナ内からの外部接続と、作業領域の外への書き込みが失敗する。seatbelt も同じ2点をテストで確かめている。
seatbelt は Docker を使えない環境のために残してある。

## 残る危険

- 依存関係の導入（`pip install`）は、エージェントが書いた `requirements.txt` に従ってネットワークありで行う。
  悪意のあるパッケージ名が書かれれば、イメージの構築時にそのコードが動く（コンテナの中に限られる）。
- seatbelt では、実験コードがホスト上の秘密でないファイルを読める。ネットワークがないので外へは出せないが、
  結果ファイルに書き込むことはできる（公開前の検査はパターン照合であり、完全ではない）。
- エージェント CLI 自体はネットワークを使う。読み取り専用の道具でも、読んだ内容がモデルの提供元に送られる。
- プロンプトインジェクションへの対策は、権限を絞ることが主で、文章による指示は補助にすぎない。
