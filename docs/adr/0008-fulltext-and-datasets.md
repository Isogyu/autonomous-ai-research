# ADR-0008: 論文の本文と公開データセットの扱い

- 日付: 2026-11-24
- 状態: 採用

## 状況

初期バージョンでは、企画も研究も論文の要旨だけに基づき、実験のデータはコードで生成するものに限られていた。
要旨だけでは手法の詳細や数値が分からず、合成データだけでは確かめられる問いが狭い。

## 決定

### 論文の本文（`aar/sources/fulltext.py`）

- 取得元は arXiv の HTML 版を優先し、無ければ PDF（arXiv、または情報源が示すオープンアクセスの PDF）。
  PDF は pypdf で文章にする（任意の依存 `.[fulltext]`）。arXiv へのアクセスは3秒に1回以下。
- 本文は読むだけで再配布しない。保存先は `var/papers/`（Git の対象外）。DB には取得元・取得日時・ハッシュ・文字数だけを残す。
  研究のリポジトリ（公開候補）にも、公開候補に写す監査記録にも入れない。
- 使う場面は、企画の生成、研究理解、独立監査（原論文との整合性の確認）。エージェントには外部由来のデータとして囲んで渡す。
- 本文を渡していないのに「本文を読んだ」と記録されることを防ぐ（エージェントの申告ではなく、渡したかどうかで決める）。
- 取得できなければ要旨で進め、成果物にもそう書かれる。

### 公開データセット（`aar/datasets.py`）

- 実験コードはネットワークなしのまま。外部のデータは、設計に書かれた URL を**オーケストレーターが実験の前に取得する**。
- 取得できるのは、方針（`safety.dataset_hosts`）で許したホストの https の URL だけ。転送は自分でたどり、各段のホストを確かめる。
  1ファイルの大きさに上限（既定 200MB）。圧縮ファイルは展開しない（展開は実験コードが隔離環境の中で行う）。
- ライセンスが書かれていないデータは取得しない。
- 取得は**事前登録の前**に行い、ファイルのハッシュを事前登録の内容に含める。実験の後でデータを差し替えると、
  品質ゲート（事前登録の確認）で検出される。取得できなかった場合は、その理由を渡して設計をやり直させる（2回まで）。
- データそのものは `data/external/` に置き、Git に入れない（第三者のデータを再配布しないため）。
  代わりに、取得元・ハッシュ・ライセンス・取得日時の記録（`MANIFEST.json`）と、取得し直すスクリプト（`tools/fetch_data.py`）をコミットする。
- 研究監査の複製には外部データを写す（生データからの再計算に必要）。公開品質監査の複製には写さない（公開されるものだけを見せる）。

## 理由

- エージェントや実験コードにネットワークを開くより、取得をオーケストレーターの決まった処理に限る方が、
  送信先とデータの出所を管理しやすい。
- ハッシュを事前登録に入れることで、「どのデータで検証するか」も実験前に固定できる。

## 確認したこと（2026-11-24）

- 本文: 企画の原論文5件（すべてオープンアクセスの PDF）と、arXiv の HTML 版1件で取得できた。
- データ: GitHub（raw.githubusercontent.com）と Hugging Face（転送あり）から小さな CSV を取得し、取得し直すスクリプトでハッシュが一致した。
- ホストの制限、転送先の確認、大きさの上限、ライセンスの必須、Git に入らないこと、差し替えの検出は自動テストで確かめている。

## 限界

- **本文と公開データを使った研究を、最初から最後まで実際に走らせてはいない。** 確認したのは取得の処理と、つなぎ込みの自動テストまで。
- PDF から取り出した文章は、表・数式・段組みが崩れる。図は読めない。
- 設計担当は URL を自分の知識から書くので、実在しない URL を書くことがある（取得の失敗で検出し、設計をやり直す）。
  データを探すための検索の道具は渡していない。
- ライセンスは設計担当の記述を記録するだけで、取得元の実際の利用条件と照合していない。公開品質監査 Skill が権利の根拠を確認するが、
  最終的な判断は人が行う必要がある。
- 許可するホストは少数に絞っている。足す場合は方針ファイルを変える（実行中の研究は保留になり、明示的な取り込みが要る）。
