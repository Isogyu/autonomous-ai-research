# ADR-0003: 研究エンジン — 事前登録つきの仮説検証は内蔵エンジン、AI Scientist v3 はアダプターで外付け

- 日付: 2026-11-23
- 状態: 採用（AI Scientist v3 の接続は未完了）

## 状況

第一候補は AI Scientist v3（SakanaAI/AI-Scientist-v3、Apache-2.0、0.1.0 Alpha、コミット `f8ae47d` を調査）。
コードを読んで分かったこと（詳細は `docs/research/ai-scientist-v3.md`）:

- 入力は「task.md・evaluate.py・capture.py・初期プログラム」のディレクトリで、評価関数の点数（`combined_score`）を
  上げるプログラムを探す型の研究を行う。仮説・指標・判定基準を実験前に固定する工程はない。
- 費用の上限機能がない（計測だけ）。抑える手段は回数と時間の上限。
- フルパイプラインと論文生成は数 GB 規模の Docker イメージが必須。ネイティブ実行ではエージェントがホスト上で全権限で動く。
- CLI（`agsci`）、フェーズ単位の再開、JSONL のイベント、終了コードがあり、外側から制御できる。
- 内蔵の査読は OpenAI の API キーが必須。

## 決定

1. 既定の研究エンジンは内蔵の `native`（`aar/engine/native.py`）。要件の Phase A〜G（研究理解、設計、事前登録、実装、
   予備実験、本実験、分析）をそのまま工程にし、エージェントには Claude Code を使う。
2. AI Scientist v3 は外部依存として `vendor/` に置き、アダプター（`aar/engine/ai_scientist.py`）から
   サブプロセスで起動する。中身は再実装しない。探索（`agsci investigate`）だけを使い、監査と成果物はこのシステムが行う。

## 理由

- このシステムの中心は「事前登録した仮説を検証し、独立監査で確かめる」ことで、AI Scientist v3 の型（点数の最適化）とは違う。
  無理に合わせると、事前登録と探索的分析の区別という要件を満たせない。
- 一方、最適化型の研究テーマでは AI Scientist v3 の探索ループをそのまま使う方がよい。再実装はしない。

## 現状と限界

- **アダプターは実機で動かしていない。** ディスクの空きが足りず、依存関係（`uv sync`）を導入できなかった。
  コマンドの組み立てと結果の読み取りは上流のコードと文書に基づく。ワークフローにもまだつないでいない
  （エンジンに `ai_scientist_v3` を指定すると開始時にエラーになる）。
- つなぐときは、全権限実行をホストで行わないこと（専用ユーザーか仮想マシン）と、コミットの固定が条件。
